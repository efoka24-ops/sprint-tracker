Tu rédiges une spécification à partir de : $ARGUMENTS

1. Détermine le prochain numéro en regardant `specs/`, puis crée
   `specs/NNN-nom-court/spec.md` à partir de `.specify/templates/spec-template.md`.
2. Écris **ce qui doit être vrai pour l'utilisateur**. Aucun nom de table, aucune
   route, aucune bibliothèque : cela relève du plan.
3. Chaque récit porte des critères d'acceptation vérifiables, formulés
   « étant donné / quand / alors ».
4. Remplis le tableau des rôles : qui peut quoi, et qui **ne voit pas l'écran**
   (constitution I).
5. Tout ce que la demande ne tranche pas devient une entrée explicite dans
   « Ce qui reste à trancher ». N'invente pas une valeur métier : une hypothèse
   silencieuse coûte plus cher qu'une question.
6. Les critères de succès se mesurent sur les données réelles (constitution VI).

Termine en listant les points non tranchés qui bloquent le passage au plan.
